# CiderDeck Agent Guide

## Product

CiderDeck is a touch-optimized Linux dashboard for the Corsair Xeneon Edge. It is built with C++20, Qt 6.5+, and Qt Quick/QML, targeting KDE Plasma on Wayland while retaining reduced functionality when optional KDE integrations are unavailable.

Optimize for a polished command-center experience on a 2560×720 touchscreen: fast feedback, large reliable touch targets, restrained visual hierarchy, smooth navigation, and no focus stealing.

## Sources of truth

Read these before changing related behavior:

- `README.md` — supported build, run, test, preview, architecture, and dependency workflow.
- `docs/DESIGN-SYSTEM.md` — icons, colors, sliders, scaling, settings, and component conventions.
- `docs/NEXT.md` — redesign intent and isolated preview workflow; verify historical validation claims against current CMake/tests.
- `docs/ROADMAP.md` — deferred features and known KDE/Wayland limitations.
- `CMakeLists.txt` — authoritative sources, optional feature gates, resources, and current test targets.
- `pkg/PKGBUILD` — Arch dependencies and packaging behavior.

Do not commit personal layout data or monitor/application/location identifiers from `~/.config/ciderdeck*`.

## Architecture

- `src/app/` is the composition root and QML context registration layer.
- `src/models/` owns persistent configuration and domain data.
- `src/viewmodels/` owns presentation-facing state and grid/editing logic.
- `src/services/` owns Linux, KDE, D-Bus, PipeWire/PulseAudio, process, and external-system integrations.
- `src/qml/` owns the dashboard shell, pages, overlays, settings, and tiles.
- `src/resources/` and `src/qml/qml.qrc` register compiled assets and QML.
- `tests/` contains QtTest, QML, lint, and CMake contract checks.

Keep system integration in C++ services and presentation/interaction in QML. Expose narrow properties, signals, and invokables; do not duplicate service state in QML without a clear reason.

## Change workflow

1. Run `git status --short --branch` before editing. The working tree may contain active user work; preserve modified and untracked files and never reset, clean, stash, or rewrite them without explicit permission.
2. Read the relevant implementation, declarations, registrations, resources, callers, tests, and neighboring components before changing a symbol.
3. For bug fixes, reproduce or characterize the failure and fix the underlying class of problem, including sibling call paths where appropriate.
4. For behavior changes, add or update tests first when practical:
   - model/viewmodel logic: QtTest targets under `tests/`
   - service settings and deterministic service behavior: service QtTest targets
   - QML logic: `tests/qml/`
   - cross-file visual contracts: focused CMake verification scripts
5. Keep optional integrations conditional and failure-tolerant. CiderDeck must still configure and run with reduced integration when optional KDE libraries or tools are absent.
6. Register every new C++ source in `CMakeLists.txt`, every QML file in `src/qml/qml.qrc`, and every bundled icon in `src/resources/icons.qrc`.
7. Use `LucideIcon` and existing theme roles for UI actions. Use system/app icons only for external applications or content, following `docs/DESIGN-SYSTEM.md`.
8. If dependencies change, update both CMake discovery/linking and `pkg/PKGBUILD`. Do not bump versions or prepare releases unless the task calls for it.
9. Update user-facing documentation when workflows, configuration, dependencies, or limitations change.

## Verification

From the repository root, the normal quality gate is:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build -j"$(nproc)"
ctest --test-dir build --output-on-failure
```

CTest currently includes model, clipboard, service-settings, QML lint, QML behavior, and tile-scale contract checks. Run a focused test during iteration, then the complete gate before declaring a substantive change complete.

For visual or interaction work, use an isolated preview configuration rather than the installed dashboard's live data:

```bash
cmake -S . -B build-next -DCMAKE_BUILD_TYPE=Debug
cmake --build build-next -j"$(nproc)"
CIDERDECK_CONFIG_DIR="$HOME/.config/ciderdeck-next" \
  CIDERDECK_PREVIEW=1 \
  ./build-next/ciderdeck
```

Launching GUI previews, stopping or starting `app-ciderdeck@autostart.service`, using sudo, installing packages, or changing live configuration requires explicit user direction. Report hardware- or compositor-dependent behavior as unverified unless it was actually exercised on the target setup.

## Definition of done

A change is complete only when it is scoped, consistent with the design system and architecture, covered by appropriate tests, built successfully, documented where needed, and verified without disturbing the user's installed dashboard or unrelated working-tree changes. Do not commit or push unless explicitly asked.
